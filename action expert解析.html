01 / 输入是一摞表，不是一个数字

一个 token 到底长什么样？

在进入 Transformer 的这一层，一个 token 就是一行浮点数。它不是一个完整任务，也不是“悬停／下降／抓取”这些文字技能。

形状中的轴在 [32,51,768] 里不要误读成
B = 3232 个独立样本，32 张特征表同一视频连续 32 帧
L = 51每张表 51 行：状态 1 行＋动作 50 行只有一个 token／一个 51 维向量
D = 768每行 768 个数，即一个 token 的隐藏宽度768 张图／768 个动作

一个样本的动作表

S   : [ 0.12, −0.50, …, 0.40 ]
A₁  : [ 0.33,  0.27, …, −0.10 ]
A₂  : [ −0.21, 0.61, …, 0.35 ]
…
A₅₀ : [ 0.08, −0.42, …, 0.19 ]

每行各有 768 个数。此处数字只是示意。程序先安排好状态、动作的位置；位置编码进一步让网络区分动作次序。

VLM 是什么？

Vision-Language Model，视觉语言模型。这里用 Qwen3-VL：视觉编码器把图像变成特征 token，分词与 embedding 把指令变成文本 token，另外还有可学习的任务查询 token。

它们组成前缀表 [B,P,2560]。P 包括图像、语言、边界和启用的查询位置，不是固定的“图片张数”。

VLM 主干输出仍是一串向量，不会自动池化成一个向量。H_img / H_cur / H_fut 是按位置取出的片段，不是三个独立主干。

batch 轴不参与 token 之间的注意力。样本 1 的动作 token 不会去读样本 2 的图像。整批有 32×51 个动作分支 token，但不是一条 1632-token 的序列。
02 / 从轨迹到后缀 token

状态、动作和 τ 怎么进入网络？

训练样本来自演示中的一个时刻：当前三路图像、状态、指令，以及对应的后续专家动作块。批次是打乱采样的样本；一个样本内部的图像和动作保持配对。

构造带噪动作，不是直接输入专家答案

真实动作块记为 A，同形状高斯噪声记为 ε。随机取生成进度 τ，构造：

xτ = (1 − τ) A + τ ε
uτ = ε − A   ← 监督目标，不是输入 token

τ 读 tau，近似“套”。它不是录像时间戳，也不是动作块第几步；同一数据再次训练时可获得不同 τ 和 ε。每个样本一个 τ，50 步动作共用。

0.70
示例 A = 0.5，ε = −0.3：τ = 0.7 时 x = −0.06，目标 u = −0.8。
这是一个分量的教学例子。端点可用于理解；训练默认随机采样并缩放到约 (0.001,1)。源码的 sample_beta 是自定义均匀随机数变换，不应仅按函数名断言是标准 Beta 分布。

动作先投影，时间再融合

操作形状（默认每卡 B=32）
RoboTwin 有效动作整理并补齐[32,50,14] → [32,50,55]
带噪动作经 action_in_proj[32,50,55] → [32,50,768]
τ 经正弦编码；重复到每个动作位置[32] → [32,768] → [32,50,768]
动作、时间沿特征轴拼接[32,50,768] + [32,50,768] → [32,50,1536]
Linear → SiLU → Linear 融合[32,50,1536] → [32,50,768]

这里的“＋”表示拼接，不是逐元素相加。50 个动作仍是 50 个 token，只改变每行的宽度。时间不是另外加第 52 个 token。

前面加 1 个状态 token

state: [32,55] → state_proj → [32,1,768]
concat(state token, 50 action tokens) → [32,51,768]

这是送入 Action Expert 的后缀表。同一时间编码还走一条独立的条件路径 ada_cond，调制动作层的 AdaRMSNorm；官方配置启用了 adanorm_time。不是第二个不同的 τ。

两种速度要分清：uτ 和网络预测的 vτ 是动作生成空间中的变化率，不是机械臂在真实时间中的关节速度。
03 / 你已经熟悉的算法

普通单头自注意力：一张表、一套投影

设一张输入表 X ∈ ℝL×D。同一层里所有位置共用这一层的三套参数：

Q = X WQ   K = X WK   V = X WV
S = Q Kᵀ / √dk
α = softmax每一行(S + M)
O = α V
概念确切含义易懂比喻（不是实际文字）
Q / Query每个位置的匹配查询向量“我按什么特征找信息”
K / Key每个位置供匹配的特征向量“我能被什么查询找到”
V / Value最终会被加权汇总的内容向量“被读取时我提供的信息”
分数 S缩放后的 q·k 相似度匹配程度，还不是概率
权重 α一行分数经 softmax 的结果给各个来源分配多少读取比例
结果 O按 α 加权求和的 V当前位置汇总到的信息

更新第 i 个位置，就用第 i 个位置自己的 qi，匹配允许读取的所有 kj，包括自身。不是每个 q·k 配对单独做 softmax，而是一整个查询行一起归一化。

Q、K、V 是三个不同投影；“共享”说的是所有 token 位置复用这些参数。输入行不同，所以生成的 q/k/v 不同。不同 Transformer 层通常不共用这一套参数。

04 / 核心疑惑：768 怎么乘 2560？

不乘原始 token，乘投影后的 Q 和 K

VLM 分支

输入 XV: [B,P,2560]

QV = XV WQV
KV = XV WKV
VV = XV WVV

这一支的所有 token 共用自己的投影。

动作／状态分支

输入 XA: [B,51,768]

QA = XA WQA
KA = XA WKA
VA = XA WVA

51 个位置共用动作支投影；不是每行一套。

先只看一个 128 维注意力头

[51,768] × WQA[768,128] → QA[51,128]
[P,2560] × WKV[2560,128] → KV[P,128]
QA KVᵀ : [51,128] × [128,P] → [51,P]

原始宽度一个 768、一个 2560；真正相乘的内维度都是 128。投影是可学习线性变换，可改变宽度，不是硬把原始向量切成几块，也不是简单补零。

投影后才合并 token 轴

Q = concattoken轴(QV, QA)
K = concattoken轴(KV, KA)
V = concattoken轴(VV, VA)
O = softmax(Q Kᵀ / √dk + M) V
谁的 Q ↓ ／ 谁的 K →VLM 的 K动作／状态的 K
VLM 的 QQVKVᵀ
前缀读取前缀		QVKAᵀ
前缀读取后缀（这里被 mask 禁止）
动作／状态的 QQAKVᵀ
后缀读取前缀		QAKAᵀ
后缀读取后缀（按规则）
概念边界：可把这里理解为“分支专用投影的联合／异构自注意力”。它不等于标准层中所有位置共享同一套 W，但 attention 的核心算法相同。动作读视觉这一块具有 cross-attention 的跨分支作用；实现却是联合拼接 Q/K/V，而非先另跑一个完全独立的交叉注意力层。“联合注意力”这个泛称本身也不保证任何模型都用这套实现。
05 / 一个例子，走完全部计算

“抬锅”：5 个 token 的单头实验台

只看一个样本：VLM 有图像 I、文字 L 两行；动作支有状态 S、动作 A₁、动作 A₂ 三行。把 VLM 宽度缩成 4，动作宽度缩成 3，注意力头缩成 2，便于手算。

以下所有向量和 W 都是人为设定的教学数字，不是 LingBot 权重。I／L 的标签只标来源，不代表某一维有固定语义。A₁／A₂ 表示已经融合时间的带噪动作 token，不是实际关节角。为聚焦矩阵计算，本例省略 norm、Q/K norm、RoPE、bias、AdaNorm 和多头；真实网络有这些步骤。

③ 用自己的 Q 与所有 K 算分数

以 A₁ 为例，q=[1,0]，得到原始点积 [2,0,0,0.5,0.5]。除以 √2，得到约 [1.4142,0,0,0.3536,0.3536]。

qA₁·kI = [1,0]·[2,0] = 2；缩放分数 = 2/√2 ≈ 1.4142。

④ mask 后，对这一整行一起 softmax

本例官方规则下 A₁ 可以读五个位置。softmax 是“先取指数，再除以这一行所有允许位置指数的总和”。视觉和动作列在同一个分母里竞争，不各自归一化。

⑤ 同一行权重，加权汇总对应 V

A₁ 汇总图像、文字、状态和两个候选动作的信息，结果仍然是一个 2 维向量。

为什么动作输入没图像也能读图像？因为图像的 K/V 也参加了这次联合 attention。动作 q 匹配图像 k 后，将图像 v 加入自己的加权结果。不是凭空推断，也不是把 4 维图像原始 token 加进 3 维动作 token。

⑥ 拆回分支，投影回原宽度，再走各自 FFN

联合结果 O: [5,2] 的前 2 行拆回 VLM、后 3 行拆回 Action。两支分别使用输出矩阵：

WOV = [[1,0,1,0], [0,1,0,1]]   （2×4）
WOA = [[1,0,0], [0,1,1]]   （2×3）

本例再用一个明确但非常简化的前馈层：FFNV(z)=0.1×ReLU(z)，FFNA(z)=0.2×ReLU(z)。每支都计算 z=x+OWO，然后 h=z+FFN(z)。这可视为特定权重下的两层 ReLU MLP，不是实际模型的 norm 或 MoE。

宽度回到 VLM 的 4／Action 的 3，token 行数各自不变；接下来可以进入下一层。真实网络对应回到 2560／768，动作分支用配置启用的 MoE FFN。两支不独立于信息和训练梯度，只是拥有各自参数。

06 / 箭头不是机械臂运动方向

信息读取方向 = 谁的 Q 可以用谁的 K/V

“动作读取图像”说的是 q_action 匹配 k_image 并汇总 v_image。反方向是另一个计算：q_image 去读动作的 K/V。允许 A 读 B，不意味着自动允许 B 读 A。

读取者 ↓ ／ 来源 →I 图像L 文字S 状态A₁ 动作A₂ 动作
I 图像允许禁止禁止禁止禁止
L 文字允许允许禁止禁止禁止
S 状态允许允许允许禁止禁止
A₁ 动作允许允许允许允许允许
A₂ 动作允许允许允许允许允许

这张表是五个教学 token 的简化。真实前缀包含很多图像、文字、查询位置；规则按位置与有效性构造，不是按人类理解的物体类别构造。

为什么动作之间双向？

一次前向要修正整段候选动作。A₁ 可读 A₅₀，A₅₀ 可读 A₁，让不同动作位置协调。此处读取的是带噪候选，不是直接暴露未来专家真值 A。

这不是语言模型那种“只看先前位置，逐个生成下一个词”的动作自回归。

为什么前缀不读后缀？

观测表示不能被这次候选动作写回；状态也不读动作。推理时前缀可先计算并缓存 K/V，再供多轮动作积分复用。

官方 RoboTwin YAML 的 vlm_causal: true 使前缀内部因果；不要照旧图把它说成全双向。

更正旧架构图的表述：本页依据实际源码：前缀按官方设置因果，50 个动作位置在一个块内双向。原图若写“观测双向、动作逐步因果”，不能作为这份配置的依据。本次仅新建学习页，没有修改原图。

mask 怎么让权重变成 0？

允许：Mij = 0
禁止：Mij = −∞ → exp(−∞) = 0 → αij = 0

这是数学等价解释。实际代码用布尔／块 mask，不一定真的存一个浮点 −∞ 矩阵。pad_masks 排除填充位置；att_masks 定义块／因果规则，二者合成二维 mask。完整训练的逻辑形状为 [B,P+51,P+51]，没有跨 batch 的读取。

07 / 分支数不是头数

多头：把刚才的单头计算并行做多份

“联合”解释哪些来源的 token 一起计算；“多头”解释有多少组投影后的匹配子空间并行计算。这两个概念互不替代。

本地 V2 默认设置数值含义
动作隐藏宽度768输入／残差表的一行宽度
查询头数3232 组 Q
K/V 头数8每 4 个查询头共享 1 组 K/V，称 GQA
每头宽度128每次 q·k 的匹配维度

不是 768÷32=24 维／头。先用线性层投影：Q 总宽 32×128=4096，K/V 总宽 8×128=1024。线性投影允许输出比输入更宽。

分支全部查询头的 WQ全部 K/V 头的 WK、WV输出 WO
VLM（按兼容的 Qwen 配置）[2560,4096][2560,1024][4096,2560]
Action（默认）[768,4096][768,1024][4096,768]
这里用行向量右乘 W 的数学记法；PyTorch Linear.weight 的存储顺序为 [输出宽度,输入宽度]，所以源码看到的矩阵轴顺序可能正好相反。每头 W 是完整线性层输出列的一个块，不要求实际存成 32 个独立对象。

投影与联合后的实际布局

QA: [B,51,32,128]   KA/VA: [B,51,8,128]
QV: [B,P,32,128]   KV/VV: [B,P,8,128]
联合 Q: [B,P+51,32,128]
联合 K/V: [B,P+51,8,128]

GQA 用分组共享关系让 32 组 Q 与 8 组 K/V 匹配；每个样本、每个查询头、每个查询位置仍各自对候选 key 位置做一次 softmax。softmax 不跨头、不跨 batch；它沿 key/token 轴归一化。

多头结果拼成 4096 宽，再经各支的输出投影回 2560／768。你已经懂的单头机制重复多份而已。这里的“注意力头”也不是深度／视频的四个辅助“预测头”，更不是 MoE 的 32 个 FFN 专家。

08 / 特征、速度、最终动作是三件事

输入与输出形状，最后对一次

阶段默认形状是什么
Action Expert 的后缀输入[32,51,768]状态＋融合 τ 的带噪动作特征
36 层后的后缀隐藏输出[32,51,768]通过视觉／语言条件更新的特征；不是关节角
只保留最后 50 个动作位置[32,50,768]丢掉状态位置的输出
action_out_proj 的输出[32,50,55]预测 Flow 速度 vτ；训练匹配 ε−A
推理从 τ=1 积分到 0[B,50,55]得到模型动作块；部署通常 B=1
恢复 RoboTwin 顺序、反归一化[B,50,14]真实关节目标＋夹爪目标；可以交给环境

训练用专家 A 来构造 xτ 和监督目标。部署没有专家 A：先采样噪声，固定这次观测条件，多轮预测速度并更新整段 x：

x ← x + Δτ · v̂τ   （Δτ < 0，τ 从 1 降到 0）

每轮都更新整段 50 步；不是“第1轮只生成动作1，第2轮只生成动作2”。去噪／积分次数、动作位置、录像时间、训练 batch 是四个不同概念。

训练与推理组织不同，但读取逻辑一致：训练可联合处理 prefix＋suffix；推理先算 prefix 的每层 K/V 缓存，再让动作 Q 读取缓存和本轮动作 K/V。因为 prefix 不读取 suffix，它不需要随每轮候选动作重新更新。
09 / 把原来的疑惑逐条留在这里

下次忘了，先查这几问

“[32,51,768] 是输入，那到底是多少个 token？”

每个样本 51 个 token，每个 token 768 个数。32 个样本各自有一串，整批 1632 个位置但彼此不串联。不是一列标量，也不是一个 768 维向量代表整段动作。

“动作输入里只有状态和动作，视觉信息从哪里进来？”

从联合注意力的 VLM K/V 进来。动作 token 的 q 与图像／文字 token 的 k 匹配，再把对应 v 汇总进自身。不是额外增加原始图像到 [B,51,768]，也不是让另一批样本提供图像。

“768 维动作怎么乘 2560 维视觉？”

不直接乘。动作经自己的 WQ，视觉经自己的 WK，投影后的每头 q/k 同为 128 维。原始宽度不同不会阻止投影结果内维度相等。

“普通自注意力共用 W，联合注意力每个 token 用不同 W？”

更准确：普通层内所有位置通常共享一套；这里是每个分支一套。所有状态和动作共享动作支矩阵，所有 VLM token 共享 VLM 支矩阵。不是 A₁、A₂各自一套。

“自己的 K 要乘别人的 Q？”

更新位置 i 时，以自己的 qi 为查询，对所有允许的 kj 计算一行匹配分数。反过来别人的 qj 也可以匹配自己的 ki，但那属于更新别人那一行，并且要由 mask 允许。

“每个 q 和每个 k 配对后，独立 softmax？”

不是每对独立。一个 q 对应一整行分数，这一行全部允许 key 共同做 softmax。不能对视觉组、动作组各做一次再相加，否则归一化和结果都变了。

“所有 token 的 V 都一定参加吗？包括自己吗？”

包括自身及所有允许位置。禁止位置权重为 0，有效性 mask 也会排除 padding。不同 V 可同被读取；K 决定匹配权重，V 决定被汇总的内容。

“这还是自注意力吗？跟 cross-attention 哪个更像？”

整个实现是各支投影后联合拼接 Q/K/V，可称联合自注意力。分数矩阵中的动作→视觉块承担 cross-attention 作用。标准 cross-attention 常只用一组来源生成 Q、另一组来源生成 K/V；不要把跨分支读取误认为一定要额外加一个独立模块。

“两套 Transformer 是否互相独立？各有 FFN 又怎么交互？”

参数分开，信息不独立。每层 attention 交换信息，之后结果按位置切回，各自 o_proj、残差、norm、FFN／MoE 更新，再进下一层。共同训练时梯度也沿允许路径回传；mask 或 detach 可限制特定路径。

“状态、时间、动作怎样区分？模型靠猜数字吗？”

程序决定输入构造和位置：第一行来自 state_proj，后50行来自 action_in_proj 与时间 MLP。位置编码区分位置；mask 区分可见规则。时间是条件向量，不是另外的时间 token。768 个维度的语义通常是分布式学习的，不能给每维硬贴物理标签。

“VLM 的主干、四个辅助头、动作专家是什么关系？”

VLM 与 Action Expert 是逐层联合注意力的两支。四个深度／视频预测头读取 VLM 输出特征，提供训练辅助监督，不是主要动作网络。动作输出来自 suffix_out→action_out_proj，不经过那四个头。

“原图里的动作隐藏形状 [B,16,d_exp] 和因果说明还能用吗？”

不能直接用于本页核对的默认50步配置。状态＋动作输入是 [B,51,768]，动作部分是 [B,50,768]。这里前缀因果、动作块内双向。16步属于别的设置或图中文字不一致，要看对应源码配置。
