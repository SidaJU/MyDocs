# 方案四修正版：LingBot-VLA 2.0 接入 GaussianDream 3D Prefix

## 结论

方案四的总体方向可行：冻结 LingBot-VLA 2.0 的主要 VLM 和 Action Expert，只训练 LoRA、3D token 适配层和 Gaussian 训练分支；训练时用 RGB Gaussian rendering loss 让 3D token 学到可渲染的空间表征，推理时关闭 Gaussian Decoder、Rasterizer 和 render loss。

原方案不能直接开训，必须先修正：

1. `add_lora_to_model()` 不会自动冻结主干，而且要求显式传入 `lora_target_modules_support`。
2. 新增 3D prefix 后，必须同步更新 prefix segment、hidden span、position ids 和 action mask 的所有调用路径。
3. LingBot VLM hidden 是 2560 维，GaussianDream Decoder 原实现默认 token width 为 2048，必须增加投影或改 Decoder 宽度。
4. GaussianDream 的 VGGT 输入是时序/多帧组织，不能直接把 LingBot 三路相机当成原实现的三帧。
5. GaussianDream 静态 appearance head 可能需要当前 RGB，不能默认只凭 `h_3d` 就能得到正确 RGB。
6. 推理时不能丢掉生成 3D token 所需的冻结 encoder 主干，只能关闭 Decoder、Rasterizer 和 loss。

## 1. 第一版目标路径

```text
当前三路 RGB
  → frozen 3D feature backbone
  → trainable multi-view adapter / query projector
  → 256 个 3D tokens，投影到 2560 维
  → LingBot VLM prefix（新增 gs_3d bookkeeping segment）
  → 3D prefix 对应的 VLM hidden
  → 2560 → d_decoder projection
  → Gaussian Decoder（训练期）
  → Gaussian primitives
  → Gaussian Renderer
  → RGB_hat
  → L_render(RGB_hat, I_t)
```

```text
L_total = L_action
        + 原有 LingBot 深度特征蒸馏损失
        + 原有视频特征蒸馏损失
        + λ_3D · L_render
        + 原有 MoE 辅助损失
```

本版本不加入未来运动头、3D flow loss 或 Gaussian depth-map loss。LingBot 原有的深度损失继续保留，它比较的是 `[B,256,1024]` 深度特征，不是 Gaussian 深度图。

## 2. 断点 1：相机参数

GaussianDream 在 [policy.py](Papers/GaussianDream/code/src/gaussiandream/models_pytorch/policy.py) 的 `_get_camera_params_for_view()` 中硬编码了 LIBERO 的 `fx/fy/cx/cy`、单位 `viewmatrix` 和固定 pose。LingBot 当前 batch 只有相机名称，没有投影参数。

新增：

```text
LingBot/configs/robot_configs/robotwin_camera.json
LingBot/lingbotvla/models/vla/geometry/camera_params.py
```

JSON 按 `camera_top`、`camera_wrist_left`、`camera_wrist_right` 保存：原始宽高、`fx/fy/cx/cy`、`T_cam_world`。参数必须从指定 RoboTwin commit 核对，不能照搬 LIBERO 常量。

相机配置可以是静态常量，不必放进每个样本的 model input；构造成 device tensor 后显存开销很小。必须处理原始 RGB、VLM resize 和 Renderer 分辨率之间的内参缩放，不能只 resize 图像而继续使用原始 K。

`get_camera_params_for_view()` 至少返回：

```text
intrinsics [B,3,3]
viewmatrix [B,4,4]
projmatrix [B,4,4]
tanfovx / tanfovy
campos [B,3]
```

## 3. 断点 2：RGB render loss

第一版只加入图像空间损失：

```text
L_render = 0.85 · L_SSIM(RGB_hat, I_t)
          + 0.15 · L1(RGB_hat, I_t)
```

可以在第一条路径稳定后再加入 LPIPS。不能复用 LingBot 的 `_emb_loss()`，因为它处理的是 `[B,N,D]` 的深度/视频特征；RGB render loss 必须独立实现。

第一版暂不加入：Gaussian depth-map L1、future RGB、future motion、3D flow 和多 horizon rollout。

## 4. Prefix 兼容改动

LingBot 的 `embed_prefix()` 在 [modeling_lingbot_vla_v2.py](LingBot/lingbotvla/models/vla/lingbot_vla/modeling_lingbot_vla_v2.py) 中并行维护：

```text
parts          # embedding 内容
masks          # pad mask
input_ids      # position-id / RoPE 计算用的占位 ID
visual_masks   # 视觉 token 标记
```

新增 3D token 必须通过 `_append()` 同步追加四组数组：

```python
_append(
    gd_tokens,                    # [B,256,2560]
    torch.ones_like(gd_pad_masks),
    gd_placeholder_ids,           # eos 等非 image id
    torch.zeros_like(gd_pad_masks),
)
```

需要增加 `gs_3d` bookkeeping segment。它只是为了记录 256 个 token 的 span，不改变 attention 类型。建议顺序为：

```text
image → language → current_depth → gs_3d → future_video → future_depth
```

必须同步修改 `prefix_query_segments()`、`prefix_query_token_spans()`、`embed_prefix()`、所有 hidden slice、`_block_suffix_to_future_video_if_enabled_()` 和 `predict_velocity()` 的调用路径。不能只改 `embed_prefix()`。

`input_ids` 使用 EOS 等非图片占位 ID，`visual_masks` 对 3D token 全 0；不能使用 image token ID，否则 Qwen3-VL 的 RoPE 会把 3D token 当成图像网格。

## 5. 3D token 生成

第一版不加入 TGE、MTA 或 temporal context，采用无时序多视角适配：

```text
camera_top / wrist_left / wrist_right RGB
  → frozen 3D feature backbone
  → trainable multi-view adapter
  → trainable query projector
  → [B,256,d_adapter]
  → Linear(d_adapter → 2560)
```

不能把三个相机直接伪装成 GaussianDream 原实现的三帧时序输入；需要显式的三视角包装和适配层。

## 6. Gaussian Decoder 适配

GaussianDream 的 [decoder.py](Papers/GaussianDream/code/src/gaussiandream/models_pytorch/decoder.py) 使用 `token_dim`，原实现默认 2048。LingBot 的 VLM hidden 是 2560，推荐：

```text
h_3d [B,256,2560]
  → decoder_in_proj: Linear(2560 → d_decoder)
  → GaussianDecoder(token_dim=d_decoder)
```

Decoder 输出 `xyz/μ`、`scales/Σ`、`opacity`、`rotations` 和 `SH/color`。如果保留 GaussianDream 的 appearance/image fusion，就必须把当前 RGB 传入 Decoder；如果第一版只让 Decoder 读 `h_3d`，必须显式关闭 image fusion。

## 7. LoRA 和冻结策略

`add_lora_to_model()` 在 [lora_utils.py](LingBot/lingbotvla/utils/lora_utils.py) 中虽然定义了 `freeze_parameters()`，但没有自动调用；同时 `lora_target_modules_support` 默认是 `None`。初始化顺序必须是：

```text
build model
→ freeze VLM backbone / vision tower / action expert
→ inject LoRA only into qwenvl language blocks
→ create 3D adapter / projection / Decoder
→ build FSDP / optimizer / torch.compile
```

必须记录可训练参数，确认只有 VLM LoRA、3D adapter、decoder projection 和 Gaussian Decoder 进入 optimizer。Action Expert、VLM 原始权重、视觉塔和 frozen 3D backbone 不应进入 optimizer。

## 8. Loss 汇聚

不要修改现有 forward tuple 长度。新增 render loss 在模型内部加入 `total_loss`，同时写入已有 `loss_dict`：

```python
total_loss = (
    loss_vla + loss_depth + loss_future_depth + loss_future_video
    + loss_render + seq_wise_loss + router_z_loss
)
loss_dict["render_loss"] = loss_render.detach()
```

必须检查 `L_render.backward()` 后，3D adapter、token projection 和 LoRA 有非零梯度；VLM 原始参数和 Action Expert 原始参数没有梯度。

## 9. 推理路径

推理时关闭 Gaussian Decoder、Gaussian Renderer 和 render loss，但保留：

```text
冻结的 3D feature backbone
3D adapter / query projector
3D prefix token 生成
VLM LoRA
```

不能把整个 3D encoder 丢掉，否则无法在线生成 3D prefix。

## 10. 执行顺序和验收

### A. 组件 smoke test

1. 读取三套相机配置并验证投影矩阵。
2. 用随机 token 测试 Gaussian Decoder。
3. 用随机 Gaussian 测试 Rasterizer 输出 RGB。
4. 测试 `compute_rgb_render_loss()` 输出有限标量。

### B. 单 batch prefix test

1. 检查 `parts / masks / input_ids / visual_masks` 长度一致。
2. 检查 `prefix_position_ids` 不报错。
3. 检查 `gs_3d` hidden span 为 `[B,256,2560]`。
4. 检查 suffix action mask 没有错读 future-depth span。

### C. 梯度 test

1. 单次 forward/backward。
2. 确认 render loss 能回传到 3D adapter 和 LoRA。
3. 确认 VLM 原始参数和 Action Expert 没有梯度。

### D. 小规模过拟合

先用很小的数据子集跑 50～100 步，要求 `render_loss` 下降、`RGB_hat` 不全黑/全灰、Gaussian 参数有限、LoRA gradient 非零、无 NaN/Inf。通过后再启动多卡正式训练和 LoRA / 全量 / 有无 3D 分支消融。

## 最终判定

修正版具备可行性，但不能按原方案直接启动 1～2 万步训练。必须先完成相机投影、prefix 长度与 position ids、Decoder token width、LoRA 冻结/target modules、render loss 梯度和小规模过拟合测试。
