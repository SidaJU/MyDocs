# 断点 1 实现规格：给 LingBot 补上相机内外参

## 背景
LingBot 的数据和模型里只有相机名字（`camera_top` / `camera_wrist_left` / `camera_wrist_right`，见 `configs/robot_configs/robotwin.yaml:42-47`），**没有相机内参 K 和外参 T_cam**。而 Gaussian 渲染需要把 3D 高斯投影到图像平面——没有 K/T，`RGB_hat` 算不出来。

GaussianDream 自己是硬编码 LIBERO 相机（`policy.py:2242-2316` 的 `_get_camera_params_for_view`，fx=fy=221.7、单位 viewmatrix），我们不能照搬，要用 RoboTwin 的相机参数。

---

## 要产出两个文件

### 文件 1：`configs/robot_configs/robotwin_camera.json`（静态相机配置）

按三个视角名组织，每个视角存：
- `width` / `height`：原始图像分辨率（RoboTwin 是 320×240）
- `fx` / `fy` / `cx` / `cy`：内参
- `T_cam_world`：4×4 外参矩阵（相机相对世界/基座）

结构示意（**数值必须真实，不能编造**）：
```json
{
  "camera_top": {
    "width": 320, "height": 240,
    "fx": <从 RoboTwin 配置读>, "fy": <...>,
    "cx": 160.0, "cy": 120.0,
    "T_cam_world": [[...], [...], [...], [...]]
  },
  "camera_wrist_left": { ... },
  "camera_wrist_right": { ... }
}
```

**数值来源**：从你 pin 的 RoboTwin commit `13c3c47ff4312dd62484bcd51be034af55c062d1` 的 `envs/camera/camera.py` 与 `envs/_GLOBAL_CONFIGS.py` 里读；或由相机 FOV + 320×240 分辨率反算（fx = width/(2·tan(fov_x/2))）。

⚠️ **必须用对版本**：RoboTwin 有过重新渲染导致 FOV 从 37° 变 43° 的先例，错版本的 K 会让投影全错。

### 文件 2：`lingbotvla/models/vla/geometry/camera_params.py`（查表工具函数）

实现：
```python
def get_camera_params_for_view(view_name: str, device, batch_size: int,
                               target_size: tuple[int,int] | None = None) -> dict:
    """从静态配置查表，构造 Gaussian rasterizer 需要的相机矩阵。

    Args:
        view_name: 'camera_top' / 'camera_wrist_left' / 'camera_wrist_right'
        device: 输出 tensor 所在设备
        batch_size: 沿 batch 维 expand
        target_size: 若不传则用原始 320×240；若传（如 256²），内参要按分辨率缩放
    Returns:
        dict with:
          intrinsics [B,3,3], viewmatrix [B,4,4], projmatrix [B,4,4],
          tanfovx, tanfovy (scalar), campos [B,3]
    """
```

实现要点：
1. 读 JSON，按 `view_name` 取参数。
2. 若传了 `target_size`，按比例缩放内参：`fx *= W_new/W_old`、`fy *= H_new/H_old`、`cx *= W_new/W_old`、`cy *= H_new/H_old`。**不能只 resize 图像却用原始 K**。
3. 构造 `viewmatrix`（从 `T_cam_world` 求逆或直接是它，取决于约定——参考 GaussianDream 里的单位阵/相机位姿处理）。
4. 投影矩阵：照搬 GaussianDream `policy.py:2255-2304` 的 `getProjectionMatrix(znear=0.01, zfar=100, fovX, fovY)`，`projmatrix = proj_base @ viewmatrix`。
5. `campos` 从 viewmatrix 求逆取平移部分（`viewmatrix_inv[:, :3, 3]`）。
6. 所有张量 expand 到 `[B,...]` 并 `.to(device)`。

---

## 三个必须注意的坑

1. **版本**：K 必须来自 pin 的 commit `13c3c47`，不能用网上别的版本（FOV 改过）。
2. **分辨率缩放**：RoboTwin 原始 RGB 320×240，VLM 用 224²，Gaussian rasterizer 可能用 128²/256²。内参必须随目标分辨率缩放。
3. **命名统一**：配置 JSON 用 `camera_top`/`camera_wrist_left`/`camera_wrist_right`（LingBot 的 key），和调用处保持一致；不要和 RoboTwin 原始 `cam_high`/`cam_left_wrist` 混用。

**静态常量，不进 batch**：不需要把 K/T 塞进每个样本。函数查表 + expand 即可，显存可忽略。

---

## 验收标准
1. 给 `camera_top` 能返回合法的 3×3 内参、4×4 viewmatrix/projmatrix。
2. 内参在 320×240 和 256² 两种 `target_size` 下都正确（缩放对）。
3. 输出形状 `[B,3,3]` / `[B,4,4]` / `[B,3]`，在指定 device 上。
4. 用几个随机 3D 点测试投影：投到图像平面的坐标落在合理范围（大致在画面内），不是 NaN/Inf。

---

## 与断点的关系
- 本文件只负责"提供相机参数"。
- 相机参数将被 `gd_render`（Gaussian rasterizer）使用，把 3D 高斯投影成 `RGB_hat`。
- 不依赖 GPU，可在开发机上做纯 CPU 单元测试。
