Mixture of Experts · 混合专家

MoE 解析

你已经懂 token、投影和注意力。MoE 主要改变的不是 Q/K/V，而是 Transformer 中“注意力之后的前馈网络”：从“所有 token 共用一个网络”变成“每个 token 选少数几个网络”。

00 / 先记住主干

MoE：很多个小网络，只调用选中的少数

MoE 全称 Mixture of Experts，混合专家。“专家”在这里是一组有自己权重的前馈网络 FFN / MLP，不是人，也不是整个 Transformer。

不用 MoE：Dense FFN

一个 token 进来 → 交给这一层唯一的 FFN → 输出更新特征。

其他 token 也使用同一个 FFN 的权重，但是输入不同，所以输出通常不同。

用 MoE：多个 Expert FFN

一个 token 进来 → router 评分 → 选择 top-k 个 FFN → 各自处理同一个输入 → 按权重加起来。

其他 token 可以选另一组专家；同一专家的权重在被它接收的 token 之间共享。

最核心的对比：注意力决定“这个 token 从哪些其他 token 读取信息”；MoE 路由决定“这个 token 交给哪些 FFN 加工”。一个是在 token 之间找信息，一个是在参数网络之间选加工路径。

可以类比“一个通用工作台”与“多台设备＋分配器”。但不要把专家硬说成“抓取专家”“抬锅专家”：这些名字不是人工预设，是否形成特定专长要靠实验分析。

01 / 不用 MoE 时究竟在做什么

先弄懂普通 FFN，MoE 就不神秘了

FFN = Feed-Forward Network，前馈网络。MLP（多层感知机）也是常用叫法。这里不是说整个模型没有反馈，而是指这块小网络按固定层次从输入计算到输出。

最简单的两层 FFN：
FFN(x) = ReLU(x W₁) W₂
[D] → Linear(D→m) → 激活 → Linear(m→D) → [D]
概念你可以怎样理解
Linear / 线性层你熟悉的 x×W：重新组合输入数字，并可改变向量宽度。
中间宽度 m加工时使用的隐藏特征数量。先扩展、再投影回 D，是常见设计。
激活函数非线性变换，例如 ReLU 把负数变为 0。不然两次纯线性变换仍可合成一次线性变换。
同一层共享 FFN这一层每个 token 都用同一组 W₁、W₂；不同 Transformer 层通常各有自己的权重。
输出仍是 D 维特征，不直接等于机器人动作。残差还会把它与原特征相加。
不用 MoE 不等于不用 Transformer，也不等于所有 token 输出一样。它只是继续使用普通的共享 Dense FFN。图像／文字信息的交换仍由前面的注意力完成。
02 / MoE 不替代整个模型

同一个 Transformer block，换掉 FFN 那一块

这里的专家不是注意力头。多头注意力是多组 Q/K/V 匹配；MoE 专家是多组 FFN 权重。两者可以同时存在。LingBot 的四个辅助预测头也是另一件事，不是四个 MoE 专家。

一个 MoE 层：y(x) = Σe∈选中的专家 wₑ Eₑ(x) [+ S(x)]
Transformer 的残差输出：hnew = hattention之后 + y(Norm(hattention之后))

Eₑ 表示第 e 个专家网络，wₑ 是该 token 对它的权重，S 是可选共享专家。专家都接收同一个完整的 token 向量，各自输出同样宽度的向量，再相加；不是把 768 维输入切成四段分别处理。

03 / 小网络挑选大网络

router、top-k、权重分别是什么意思？

router：给每个专家一个分数

router（路由器）通常是一层可学习的线性投影，作用于当前 token：

z = x Wrouter
输入 [D] → 分数 [N]；N 是候选专家数

这里不需要其他 token 的 K/V。它读取的是这个 token经过注意力后、已经包含观测信息的特征。

top-k：只选评分最高的 k 个

例如有 4 个专家，取 top-2：router 对四个都评分，但只选两位进行有效贡献。k 是一次为一个 token 激活几个路由专家，不是注意力头数。

归一化权重：决定选中的输出占多少

本页教学例子使用 sigmoid 评分：sₑ = sigmoid(zₑ)。sigmoid 将单个分数映射到 0–1，但所有专家的分数不会自动合计为 1。选中 top-k 后，再用选中分数之和作为分母。

wₑ = sₑ / Σj∈top-k sⱼ
本例 Σwₑ = 1；未选中专家的贡献权重为 0

也有 MoE 使用 softmax 或其他 router；MoE 这个概念不限定所有实现使用 sigmoid。LingBot 在本页核对的配置中，之后还乘一个缩放系数 4，详见第 08 节。

专家加工，按权重合并

被选中的专家各自执行自己的 FFN。比如：

y = 0.6 E₂(x) + 0.4 E₁(x)
有共享专家时：y = 0.6 E₂(x) + 0.4 E₁(x) + S(x)

不是再随机选一个输出，也不是把两个输出拼接。加权和后仍是 D 维。

对照你已经懂的注意力：attention 的 softmax 通常沿“所有允许的 key/token 位置”归一化；MoE 的路由权重在“候选／选中的专家”上计算。两个轴完全不同。
04 / 看数字与线路一起变化

同一个动作 token：不用 MoE vs 用 MoE

取一个已经经过注意力和归一化的动作 token，把真实 768 维缩成 2 维：x=[1,2]。设 4 个路由专家，默认 top-2；额外共享专家可以开关。

所有示例 W、2 维输入、4 专家和 ReLU 都是人工教学数字，不是 LingBot 权重。我们比较的是计算方式，不是证明“MoE 输出比 Dense 更好”。两个模型权重不同，输出不同完全正常。此例不含 LayerNorm、时间条件，也不复现实际 SwiGLU。

把黑盒打开 / 每个箭头都是一次明确计算

输入 → router → 每个专家内部 → 合并 → 输出

一个“专家”就是一套自己的小网络参数＋固定的计算步骤。把它写成 Expert 1 只是给这套网络编号，不是它会凭名字理解“抬锅”。下面每个专家框都展开到矩阵和每一维的乘加。

两个通道不要混淆：router 送出的是“选谁／给多大权重”；专家接收的是完整输入 x，不是 router 的评分。专家先算 E(x)，再乘路由权重。两者分别算，最后合并。

数值全部来自本页明确列出的教学矩阵，不是加载的 LingBot 权重。每步保留未舍入数字计算，显示值四舍五入。上面的概览与旧固定例子始终采用两层 ReLU、缩放1；下方改成 SwiGLU 或缩放4后不要混用上下两个结果。

① 不用 MoE：所有 token 都用这一个 FFN

W₁ = [[1,0],[0,1]]  （2×2）
W₂dense = [[1,1],[1,−1]]  （2×2）
x=[1,2] → xW₁=[1,2] → ReLU=[1,2]
ydense = [1,2] W₂dense = [3,−1]

FFN 内部对 token 独立处理，无需与别的 token 做 q·k。上面的矩阵固定下来后，每个输入都用同一套 W，不会先选专家。

② 用 MoE：先对专家评分

Wrouter = [[1,0,−1,0], [0,1,0,−1]]  （2×4）
z = x Wrouter = [x₁,x₂,−x₁,−x₂]
sigmoid(zₑ) = 1 / (1 + exp(−zₑ))

默认 x=[1,2] 时，logits 为 [1,2,−1,−2]，sigmoid 分数约 [0.7311,0.8808,0.2689,0.1192]。因此 top-2 选 E2、E1；归一化得到 E2 权重约 0.5464、E1 约 0.4536。

专家logit zsigmoid 得分 s是否选中归一化贡献权重 w专家输出加权贡献

05 / per-token，不是 per-task

一串动作 token，怎么分派给专家？

每个 token 都独立过 router。假设在同一层，三个输入分别为：

token特征（教学例子）top-2 专家是不是一定绑定任务？
动作 A₁[1,2]E2、E1不是
动作 A₂[−1,2]E2、E3不是
状态 S[1,−2]E4、E1不是

它们可以来自同一个“抬锅”样本，却选择不同专家。下一层特征与 router 都变了，专家选择可以再次改变。每层的 Expert 1 是该层自己的网络，不是全模型共同的一个 Expert 1。

收集分派
把所有选中 E2 的 token 行放在一起
→
批量计算 E2
共享 E2 权重，各行仍独立
→
归还原位置
按路由权重合并回原 token
“token 聚到一个专家”不是 attention：计算 E2 时，各行不会在这里互相读 K/V，也不会把两个样本的向量平均。分组只是为了高效矩阵乘法；最终每个结果按原 token 身份归还。

原始输入维度保持不变

LingBot 默认动作分支： [32,51,768]
展平行 → [1632,768]
router 评分 → [1632,32]
top-4 索引与权重 → 各 [1632,4]
专家加工、合并 → [1632,768]
还原 → [32,51,768]

1632=32×51。这不是一个 1632-token 的跨样本注意力序列，只是把各行摆在一起处理 FFN。MoE 不会让输出多一个“专家轴”，也不会因此输出四段动作。

06 / 更多参数，不必全都激活

为什么要 MoE？为什么也有人不用？

想得到的收益

  • 增加可学习的参数容量，但每个 token 只用少数路由专家。
  • 不同输入可走不同加工路径，有机会学到不同模式。
  • 在适当设计和高效内核下，保持主要活跃计算量在可接受范围。

这些是动机，不是自动保证精度提升。效果取决于数据、训练和实现。

Dense 的优势

  • 结构简单，不需要训练 top-k 路由与负载均衡。
  • 矩阵乘法规整，通常更容易优化和部署。
  • 不需要存放大量不参与当前计算的专家参数。

同等比较要明确总参数、活跃参数、数据、训练预算等；不能只看“有没专家”。

项目Dense FFN稀疏 MoE FFN
路由器没有通常有
每个 token 的路径一个共享 FFN选 top-k 个 FFN，可能再加共享专家
存储存一个 FFN 的参数所有专家都要存；不用≠不存在
计算固定、规整主要看活跃专家，还包括路由／分派／归并开销
输出形状[B,L,D]仍为 [B,L,D]
跨设备通信取决于并行方案若专家分布在不同设备，可额外涉及 token 分派通信
准确率／速度都需要实测，MoE 不是更快、更准的保证。

用 LingBot 的宽度算一个具体账

按默认 D=768，普通动作 FFN 中间宽度 m=2752。MoE 使用 32 个宽度512的路由专家，每token选4个，再加宽度704的共享专家：

Dense 中间宽度2752每个 token 全部使用
MoE 活跃宽度之和4×512+704= 2752，主矩阵乘量级相当
MoE 存储宽度之和32×512+704= 17088，不是 2752

实际 gated MLP 有三组主要矩阵。只计一个动作层中的这些权重与 router：

Dense：3×768×2752 = 6,340,608 参数
MoE：3×768×(32×512+704) + 768×32 = 39,395,328 参数
≈ 6.21 倍的参数；不代表 6.21 倍整模型参数或准确率
重要实现边界：上述活跃计算估计针对理想稀疏／选中路由执行，不是测速结果。核对的 LingBot eager 参考分支实际上会计算全部路由专家，再用零权重屏蔽未选者；不能套用“只算4个”的节省估计。官方 RoboTwin 设置选择 fused 实现；真实速度还受内核、设备、通信、访存和路由分布影响。

Dense 和 MoE 都有注意力、投影、归一化等其他开销。也不能仅从“top-4/32”推断整模型只用了 1/8 的参数或 FLOPs。

07 / 为什么专家会不同，router 会选？

不是人工写规则，而是一起训练

  1. 初始化：专家和 router 各有参数，通常先从初始化／已有checkpoint开始。
  2. 前向：对每个 token 打分、选专家、合并，继续计算最终任务输出。
  3. 损失：用最终动作／辅助监督评估预测误差。
  4. 反向：有效路径中的专家参数、路由权重路径和上游网络收到梯度。离散“选中了哪位”的索引本身不可导，但选中贡献权重通常可导；还有辅助训练项。
  5. 反复训练：router 与专家共同适配，形成输入相关的路径。不能仅凭名称判定某位专家专门处理某个技能。

对单个 token 的主路径，未选专家不贡献输出，也不会通过这份专家输出获得该 token 的主损失梯度。一个批次中其他 token 可能选它；辅助损失和优化器行为也要区别看，不能断言“未选专家参数永远不更新”。

08 / 由教学4选2，回到实际32选4

在 LingBot-VLA 2.0 中，MoE 在哪里？

部分本页核对的源码／RoboTwin 配置
VLM 主干Qwen3-VL 分支是 Dense；本处没有把它改成 MoE。
Action Expert36 层；MoE 替换动作分支每层的 mlp / FFN，不替换整个联合注意力。
路由专家数每层 32 位，专家中间宽度512；各层有各自专家权重。
每个 token 选择top-4，而非整段任务只选择4位。
共享专家每层另有1个，宽度704；每个 token 都经过它，不计入 top-4。
router评分线性投影强制 FP32，sigmoid 激活；选中分数归一化后乘4。
共享标量门use_shared_expert_gate: false，共享输出直接相加。
运行实现RoboTwin 配置 moe_implementation: fused；实现可有不同内核路径，不能当作实测性能保证。

实际路由权重为什么不一定合计为 1？

z = Linear(x)，s = sigmoid(z)
I = top-4(s + correction_bias)
wₑ = 4 × sₑ / Σj∈I sⱼ  （只对选中的4位）
y = Σe∈I wₑ Eₑ(x) + S(x)

先归一化到和为1，再乘4，所以最终路由贡献权重和约为4。这只是更新量的尺度控制，不是又选4次，不是求平均，也不意味着最终输出维度改变。

correction_bias 是评分校正偏置：本实现只影响选择，合并权重仍从原始 sigmoid 分数计算。配置把偏置更新速度设成0，但已加载的 checkpoint 偏置不一定为0。教学例子偏置明确设为0、缩放明确设为1；不要混为实际。

实际专家里面：SwiGLU

本例用普通两层 ReLU，是为了从你会的 x×W 出发。实际 LingBot 专家采用门控 MLP，SiLU 激活时称为 SwiGLU：

g = SiLU(x Wgate)   u = x Wup
E(x) = (g ⊙ u) Wdown
[768] → 两支各 [512] → 逐元素相乘 → [512] → [768]

⊙ 是对应位置相乘，不是点积，也不是 attention。SiLU 是一个非线性函数 SiLU(a)=a×sigmoid(a)。共享专家采用同类结构，只是中间宽度为704。

“gate”这个词出现在哪它干什么本配置情况
router / gate决定选择哪些专家及路由贡献有，32位选4位
专家内部 gate_projSwiGLU 中逐特征的门控分支仍然有，不因下项关闭而消失
shared_expert_gate共享专家输出外的额外标量门关闭；共享输出直接相加

矩阵形状（行向量右乘记法）：路由专家的 gate/up 为 [768,512]，down 为 [512,768]。PyTorch Linear.weight 存储为 [输出,输入]，查看代码时轴顺序相反。不同专家有自己的矩阵，但输出都回到768维。

不能直接在已训练权重上关掉 MoE，就得到公平的 Dense 基线。普通 FFN 与专家权重的组织、数量和训练路径不同；若要比较效果，需要准备对应 Dense 架构并做匹配预算的训练／适配实验。上面的对照解释结构，不建议随意切开关部署。
09 / 你可能会接着问

把最容易混的概念摆在一起

“32 个专家，是 32 个完整 Action Expert 吗？”

不是。Action Expert 是动作分支的整个 Transformer。32 是它某一层 MoE FFN 中的候选小网络数。36层各有自己的MoE，另外每层还有共享专家；别和整个动作模型名称混淆。

“MoE 是多头 attention 吗？也有 Q、K、V 吗？”

不是。router 通常直接从 token 经一个线性层得专家分数，不需要做 token-token 的 QKᵀ。多头 attention 与 MoE FFN 可以一起使用，分别负责读取信息和加工特征。

“是不是把一个 768 维 token 分给4位，各处理192维？”

不是。每位选中的专家接收完整768维输入，经过自己的MLP，输出768维。四个同宽输出加权相加，不是切开分工，也不是拼成3072维输出。

“专家是专门抬锅、开抽屉的，按任务选择吗？”

没有人工给每个专家固定技能标签。这份实现按每个 token 的隐藏特征选择，可能受任务信息影响，但不是用任务ID去固定路由。专家是否呈现语义专长要进一步分析。

“一个专家能同时处理很多 token 吗？”

可以。它对收到的各行共享自己的权重，并行做矩阵乘法；输出各自返回原位置。这不是把它们做 attention，也不会在这个 FFN 内混合不同样本。

“用了 MoE，输出的 token 更多吗？”

不多。输出仍是 [B,L,D]。变化在参数与计算路径，不在 token 数量。之后还要残差、下一层以及动作输出投影。

“top-4 的四个输出，最后选其中一个吗？”

不是。按路由权重加起来；如果有共享专家，再加共享输出。合并结果保留输入宽度。选中不等于四位权重都相同。

“所有32位都打分，不就仍然计算了所有专家吗？”

router 对32位打分只需一个小线性投影；真正的32个MLP计算要大得多。高效稀疏执行只分派选中路径，但参考／低效实现可能真的全算后屏蔽，必须看实际内核。

“没被选中的专家不用存吗？”

仍要存。此 token 没选它，下一个 token 或下一轮可能选它。MoE 节省的是可能的活跃计算，不意味着存储所有参数的需求消失。

“同一层同一个 token 的 router 和专家一起训练吗？”

通常是。离散 top-k 索引不可导，但贡献权重及选中专家路径可接受梯度；辅助负载均衡也训练 router。不是训练前先人工决定好每个 token 用哪位。

“一个 shared，是不是其他32位也共享权重？”

不是。shared expert 是额外的、人人都会经过的一位网络。32位路由专家之间不因为它叫shared就共享彼此权重。复用同一位专家处理多行才是同一专家内的参数共享。

“不用 MoE 就不能理解复杂场景吗？”

不是。Dense Transformer 也能学复杂能力。MoE 是增加容量和条件计算的一种设计，收益有条件；不能把 Dense 等同于没有智能。

三句话速记

1. 不用 MoE：这一层的 token 都用一个 Dense FFN。

2. 用 MoE：每个 token 打分，选少数 Expert FFN，加权合并；可另加共享专家。

3. 注意力是选信息来源，MoE 是选加工网络；输入输出的 token 形状保持不变。
